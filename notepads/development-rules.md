# 开发规定

## 一、基本原则

1. **方案执行**

   - 严格按照预定方案执行
   - 遇到问题要及时记录
   - 记录问题时要使用统一的模板

2. **最终目标**
   - 实现基础的涂鸦功能
   - 确保不影响图片的移动和缩放功能
   - 保持良好的用户体验

## 二、开发流程规范

1. **开发顺序**

   ```
   1. 基础架构搭建
   2. 图层系统实现
   3. 基础手势系统
   4. 涂鸦功能实现
   5. 手势冲突处理
   6. 性能优化
   ```

2. **代码组织**

   - 严格遵循文件夹结构和命名规范
   - 相关功能要放在对应的目录中
   - 公共类型定义放在统一位置

3. **测试要求**
   - 每个功能模块完成后进行独立测试
   - 需要测试手势冲突的边界情况
   - 在不同设备上进行兼容性测试

## 三、性能要求

1. **基本标准**

   - 涂鸦时保持流畅的用户体验（60fps）
   - 需要记录和监控性能指标
   - 发现性能问题时及时优化

2. **优化原则**
   - 优先保证核心功能的性能
   - 在保证功能的前提下进行优化
   - 记录所有性能优化的措施和效果

## 四、问题记录模板

```
问题类型：[架构/性能/功能/手势]
问题描述：
复现步骤：
临时解决方案：
待优化项：
```

## 五、代码提交规范

1. **提交信息格式**

   ```
   类型: 简短的描述

   详细描述（如果需要）
   ```

2. **类型说明**
   - feat: 新功能
   - fix: 修复问题
   - docs: 文档更新
   - style: 代码格式调整
   - refactor: 重构
   - perf: 性能优化
   - test: 测试相关
   - chore: 构建过程或辅助工具的变动

## 六、开发注意事项

1. **代码质量**

   - 保持代码清晰可读
   - 添加必要的注释
   - 遵循 TypeScript 的类型定义规范

2. **协作规范**
   - 及时同步开发进度
   - 重要决策需要团队讨论
   - 保持良好的沟通

## 七、文档维护

1. **需要维护的文档**

   - 架构设计文档
   - API 文档
   - 问题记录文档
   - 性能优化记录

2. **文档更新要求**
   - 及时更新
   - 保持文档的准确性
   - 记录重要的决策和变更
